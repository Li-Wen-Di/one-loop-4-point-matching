# Appendix A: One-loop four-point EFT matching by the method of regions

This package reproduces the off-shell one-loop four-point calculation in Appendix A of the paper.

The UV theory contains a light real scalar $\phi$ and a heavy real scalar $H$, with Lagrangian

$$
\begin{aligned}
\mathcal L_{\mathrm{UV}}={}&\frac12(\partial\phi)^2-\frac12m_L^2\phi^2
+\frac12(\partial H)^2-\frac12M^2H^2\\
&-\frac{\lambda_0}{4!}\phi^4-\frac{\lambda_1M}{2}H\phi^2
-\frac{\lambda_2}{4}H^2\phi^2.
\end{aligned}
$$

Here $m_L^2,|p_i\cdot p_j|\ll M^2$. The couplings $\lambda_0,\lambda_1,\lambda_2$ are dimensionless in four dimensions, and $\lambda_1$ is held fixed in the low-energy expansion.

The EFT is defined in a Green basis retaining equation-of-motion redundant operators; the calculation precedes finite field normalization and equation-of-motion reduction:

$$
\begin{aligned}
\mathcal L_G={}&\frac{Z_G}{2}(\partial\phi)^2-\frac{m_G^2}{2}\phi^2
-\frac{C_{4,G}}{4!}\phi^4-\frac{C_{6,G}}{6!M^2}\phi^6\\
&-\frac{C_{D,G}}{4!M^2}\phi^3\Box\phi
-\frac{C_{\Box,G}}{2M^2}(\Box\phi)^2.
\end{aligned}
$$

The inputs are the two fixed UV/EFT UFO models supplied with the package. Their Lagrangians agree with `models/UV.fr` and `models/EFT.fr`, respectively. Normal execution reads the bundled UFOs and does not require FeynRules. Users may load the `.fr` files in their own FeynRules installation and regenerate the UFOs with `WriteUFO`. The supplied UFOs use Python 3 relative imports; the EFT `.fr` uses the integration-by-parts form of the derivative operator and tree-level two-point inputs. Changing a model also requires regenerating its UFO and adapting the project checks and input hashes.

The off-shell adapter in `src/` calls FeAmGen's graph conversion and amplitude assembly while skipping its on-shell kinematic-relation stage; a standard on-shell export cannot replace this input.

The channel is the off-shell four-point process $\phi(p_1)\phi(p_2)\to\phi(p_3)\phi(p_4)$. Expressions use an all-incoming momentum convention, with $\sum_i p_i=0$ and no condition $p_i^2=m_L^2$.

- **UV:** Generate one-loop four-light-leg 1LPI graphs and calculate their hard and soft expansions, retaining heavy tree branches and tadpoles and including all external-leg permutations.
- **EFT:** Calculate the one-loop four-point 1PI graphs generated by the EFT Lagrangian truncated through dimension six.
- **Soft equality:** Substitute the tree-level matching relations and compare pole and finite parts separately to test

$$
M_{\mathrm{UV},4\mathrm{pt}}^{\mathrm{1Loop,Soft}}
-M_{\mathrm{EFT},4\mathrm{pt}}^{\mathrm{1Loop}}[C_G^{(0)}]=0.
$$

- **Hard output:** Retain the pole and finite local polynomial of the regulated hard-region amplitude for Appendix A.

Using the low-energy counting $p_i\sim m_L\sim Q\ll M$, the heavy-mass expansion of the four-point amplitude is uniformly retained through $O(Q^2/M^2)$, dropping $O(Q^4/M^4)$ and higher terms. This corresponds to truncating the EFT Lagrangian through dimension six. Light propagators in the soft region and EFT loops retain their full form.

```text
Bundled UFO models -> FeAmGen -> FORM region expansion -> OPITeR -> Package-X -> amplitude assembly and soft equality test
```

## Required environment

Users must provide the following command-line programs:

| Program | Role and requirements | Version used in the research calculation |
|---|---|---|
| Mathematica / `wolframscript` | Load Package-X and evaluate symbolic integrals | Mathematica 14.3 |
| Julia | Run the entry point and FeAmGen | Julia 1.10.12 |
| Python / SymPy | User-provided; used for orchestration, data conversion, and symbolic checks. The unified environment check reports the selected interpreter and the interpreter used by FeAmGen/PyCall. | Python 3.12.13; SymPy 1.14.0 |
| FORM / `form` | Region expansion and OPITeR tensor reduction | FORM 5.0.0 |
| QGRAF / `qgraf` | Generate Feynman graphs for FeAmGen | QGRAF 4.0.5 |

The release is tested on macOS ARM64 with the versions above. Other platforms and versions have not been validated.

Package-X, FeAmGen, and OPITeR sources are bundled in `vendor/` and loaded relative to the package root. They do not require global installation. Initialization installs the pinned Julia dependencies; initial installation may require network access. FORM and QGRAF are supplied by users.

## Connecting external executables

Executable discovery uses an explicit `config.toml` entry first, then the corresponding environment variable, and finally `PATH`. An invalid explicit path is reported as an error rather than silently falling back to another installation.

| Program | Configuration key | Optional environment variable | Name on PATH |
|---|---|---|---|
| FORM | `executables.form` | `FORM` | `form` |
| QGRAF | `executables.qgraf` | `QGRAF` | `qgraf` |
| Mathematica | `executables.wolframscript` | `WOLFRAMSCRIPT` | `wolframscript` |
| Python | `executables.python` | `APPENDIXA_PYTHON` | `python3` |

Copy the example configuration first:

```sh
cp config.example.toml config.toml
```

Leave paths empty if all four executables are available on `PATH`. Otherwise, supply absolute paths:

```toml
[executables]
form = "/path/to/form"
qgraf = "/path/to/qgraf"
wolframscript = "/path/to/wolframscript"
python = "/absolute/path/to/.venv/bin/python"
```

For example, a Mathematica installation on macOS may provide:

```toml
wolframscript = "/Applications/Wolfram.app/Contents/MacOS/wolframscript"
```

Each value is one executable path, without command arguments or extra shell quoting. The launcher must handle spaces in paths. Project adapters supply QGRAF control-file arguments and working directories and the FORM include path for bundled OPITeR; users do not edit upstream source code.

## Initialization and environment checks

If a new Python/SymPy environment is needed, the following installation example can be used on macOS or Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install sympy==1.14.0
```

An existing Python/SymPy environment can be reused. Configure its interpreter as described under "Connecting external executables". Python and all other dependencies are checked through the unified environment-check entry point below.

Run the Julia initialization command from the package root. `--startup-file=no` prevents personal Julia startup settings from overriding the executable environment:

```sh
julia --startup-file=no --project=. setup.jl --config config.toml
```

Run the unified check for all required environments:

```sh
julia --startup-file=no --project=. check_environment.jl --config config.toml
```

The check reports the actual executable paths and versions in `work/check-*/environment.toml`, `python.log`, and `interfaces.log`, and verifies:

- FORM and QGRAF exist, are executable, and can start on this system.
- The Mathematica kernel can run the required command-line calculation under the user's license.
- The Julia project and its dependencies can be loaded.
- The configured Python is executable; its path, version, SymPy version, and ability to import SymPy are checked, and the Python interpreter used by FeAmGen/PyCall is reported.
- Bundled FeAmGen, Package-X, and OPITeR files are present and accessible through their interfaces.
- QGRAF processes a generated control file for the bundled UV model, FORM runs a minimal input, and the working directory is writable.

QGRAF availability is tested with a control file, not by assuming that launching it without arguments must succeed. These are environment and interface checks, not tests of the internal OPITeR or Package-X algorithms.

On failure, inspect the indicated stage log and `status.toml` under `work/`. If the Python used by PyCall differs from the configured interpreter, rerun `setup.jl` with that configuration. Setup rebuilds PyCall in the active Julia depot; projects sharing that depot share its Python binding. A separate `JULIA_DEPOT_PATH` may be used consistently for setup, checking, and execution when isolation is needed. Initial setup uses the General and IHEP-Multiloop registries to install pinned dependencies.

## Running the calculation

After the environment check succeeds, run the entry point:

```sh
julia --startup-file=no --project=. run.jl --config config.toml
```

The workflow:

1. Generates and assembles off-shell four-point amplitudes from the UV/EFT UFO models.
2. Performs hard/soft expansion with FORM, including heavy tree branches, and checks the custom expansion and data conversions.
3. Calls OPITeR for tensor reduction in `d` dimensions.
4. Sends scalar integrals, including raised denominator powers, directly to Package-X and retains poles and finite parts.
5. Assembles UV soft, UV hard, and EFT loop amplitudes.
6. Substitutes tree-level matching coefficients and exports the symbolic soft residual and equality decision.

OPITeR and Package-X algorithms are treated as correct. Checks target the custom FORM module and the transfer of momenta, masses, denominator powers, indices, graph weights, phases, normalization, and epsilon-dependent factors between modules.

Before execution, `src/source_hashes.toml` is used to check the integrity of code, models, and upstream files; missing or modified files stop the run. Logs and intermediate files are stored in `work/`. The ZIP includes four computed `.wl` files, and `work/` is initially empty.

Every run starts with fresh diagram generation and a unique run ID. Previous results are moved into that run's `work/run-*/previous-results/` before computation. Only a complete, validated set is published to `results/`. A failed run exits with nonzero status and leaves no current success file; diagnostics remain in `work/`. Concurrent runs in the same project are rejected with a run lock.

## Reading the results

Read **all four `.wl` files** in a fresh Mathematica kernel. Replace the placeholder directory below with the extracted package directory. Load the bundled Package-X first so its functions and display rules are available. Assign each file to a variable with a semicolon: printing the entire association also prints long source hashes, which are provenance metadata rather than amplitudes.

```wolfram
(* Replace this path with the directory containing README.md. *)
SetDirectory["/absolute/path/to/AppendixA"];
Get[FileNameJoin[{Directory[], "vendor", "PackageX", "X", "Kernel", "init.m"}]];

uvSoft = Get["results/uvsoft.wl"];
uvHard = Get["results/uvhard.wl"];
eftLoop = Get["results/eft_one_loop.wl"];
softCheck = Get["results/soft_equality.wl"];

(* Display the pole coefficient and finite part of all three amplitudes. *)
{uvSoft["pole"], uvSoft["finite"]} // TraditionalForm
{uvHard["pole"], uvHard["finite"]} // TraditionalForm
{eftLoop["pole"], eftLoop["finite"]} // TraditionalForm

(* Read all three verification fields in the fourth file. *)
{softCheck["status"], softCheck["pole_residual"],
 softCheck["finite_residual"]}
```

| File / variable | Fields to read | Meaning |
|---|---|---|
| `uvsoft.wl` / `uvSoft` | `"pole"`, `"finite"` | UV soft-region four-point amplitude |
| `uvhard.wl` / `uvHard` | `"pole"`, `"finite"` | UV hard-region four-point amplitude; the finite part supplies the finite matching input |
| `eft_one_loop.wl` / `eftLoop` | `"pole"`, `"finite"` | EFT one-loop four-point amplitude, retaining symbolic tree-level Wilson coefficients and including bubbles and the sextic-vertex tadpole |
| `soft_equality.wl` / `softCheck` | `"status"`, `"pole_residual"`, `"finite_residual"` | Equality decision after tree-level substitution; the successful output is `{"PASS", 0, 0}` |

For each of the first three files, the amplitude is $M=h(\mathrm{pole}/\epsilon+\mathrm{finite})$, with $h=1/(16\pi^2)$; `pole` is the coefficient of $1/\epsilon$ and `finite` is the finite part. The calculation uses $d=4-2\epsilon$ and the paper's common MSbar convention. These are regulated amplitudes; the `pole` field must not be discarded when checking the soft equality. `input_sha256`, `integrated_sha256`, and `run_id` identify the inputs and run and are not terms in the amplitude.

The decision substitutes the following tree-level matching coefficients into the EFT loop result before comparing it with the UV soft result:

$$
\begin{gathered}
Z_G^{(0)}=1,\qquad (m_G^2)^{(0)}=m_L^2,\qquad C_{\Box,G}^{(0)}=0,\\
C_{4,G}^{(0)}=\lambda_0-3\lambda_1^2,\qquad
C_{D,G}^{(0)}=4\lambda_1^2,\qquad
C_{6,G}^{(0)}=45\lambda_1^2\lambda_2.
\end{gathered}
$$

`PASS` is written only when both symbolic residuals simplify to zero. A nonzero residual is retained and yields `FAIL`. An unresolved or incomplete calculation must not be marked as passed.

Program symbols `mh`, `ml`, `lam0`, `lam1`, `lam2`, `c4`, `cd`, and `c6` mean $M$, $m_L$, $\lambda_0$, $\lambda_1$, $\lambda_2$, $C_{4,G}^{(0)}$, $C_{D,G}^{(0)}$, and $C_{6,G}^{(0)}$. Also, `L` means $\ln(M^2/\mu^2)$ and `s`, `t`, `u` are the all-incoming Mandelstam invariants used in the paper.

``X`DiscB[s, ml, ml]`` is Package-X's dimensionless abbreviation for the part of the scalar bubble containing the branch cut. It is neither the full bubble integral nor just its imaginary part or discontinuity. The first argument is a momentum invariant; the last two arguments are **masses, not squared masses**. With the paper's integral normalization and common MSbar convention,

$$
B(s;m_L^2,m_L^2)
=\frac1\epsilon+\ln\frac{\mu^2}{m_L^2}+2
+\operatorname{DiscB}(s,m_L,m_L)+\mathcal O(\epsilon),
$$
$$
B_R(s;m_L^2,m_L^2)
=\ln\frac{\mu^2}{m_L^2}+2+\operatorname{DiscB}(s,m_L,m_L).
$$

In particular, $\operatorname{DiscB}(0,m_L,m_L)=-2$, so $B_R(0;m_L^2,m_L^2)=\ln(\mu^2/m_L^2)$. Light tadpole terms have already been evaluated using

$$
A(m_L^2)=m_L^2\left[\frac1\epsilon+1-\ln\frac{m_L^2}{\mu^2}\right]
+\mathcal O(\epsilon),\qquad
A_R(m_L^2)=m_L^2\left[1-\ln\frac{m_L^2}{\mu^2}\right].
$$

The final output contains only algebraic operations, logarithms (including the abbreviation `L`), and `DiscB`. To expand `DiscB` into square roots and logarithms, preserving the Package-X analytic continuation, use:

```wolfram
eftLoop["finite"] // X`DiscExpand // TraditionalForm
```

Keep the $+i0$ prescription when changing the analytic form: the light bubble has a two-particle threshold at $s=4m_L^2$. The compact `DiscB` form retains the full light-mass and external-momentum dependence; it has not been expanded in $s/m_L^2$.

## File tree

Release layout: `src/` and UFO directories are not expanded. `vendor/` is expanded by one level only. Release documentation, source comments, configuration examples, and user-facing messages use English.

```text
AppendixA/
├── README.md                      # English documentation shown on the GitHub home page
├── Project.toml                   # Direct Julia dependencies
├── Manifest.toml                  # Pinned dependencies and bundled FeAmGen location
├── config.example.toml            # Example external-executable paths
├── setup.jl                       # Initialize pinned Julia dependencies
├── check_environment.jl           # Check executable paths, versions, and minimal calls
├── run.jl                         # Run the calculation and soft equality test
├── src/                           # Custom calculation, interfaces, checks, and source integrity hashes
├── models/
│   ├── UV.fr                      # FeynRules source for the UV model
│   ├── EFT.fr                     # FeynRules source for the EFT Green basis
│   ├── UV_UFO/                    # Bundled UV UFO model; not expanded
│   └── EFT_UFO/                   # Bundled EFT UFO model; not expanded
├── vendor/
│   ├── PackageX/                  # Scalar one-loop integrals, including raised powers
│   ├── FeAmGen/                   # Graph generation and amplitude assembly from UFO
│   └── OPITeR/                    # Tensor reduction in d dimensions
├── results/
│   ├── uvsoft.wl                  # Symbolic UV soft amplitude
│   ├── uvhard.wl                  # Symbolic UV hard amplitude
│   ├── eft_one_loop.wl            # Symbolic EFT loop amplitude
│   └── soft_equality.wl           # Residual after tree-level matching and equality decision
└── work/                          # Environment reports, intermediate files, and logs
```
